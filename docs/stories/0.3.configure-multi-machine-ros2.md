# Story 0.3: Configure Multi-Machine ROS2 Networking

## Status: Draft

## Story

**As a** builder,
**I want** ROS2 configured for multi-machine communication over WiFi,
**so that** my PC can discover and interact with ROS2 nodes running on the Pi.

## Acceptance Criteria

1. PC and Pi connected to same WiFi network
2. Both machines can ping each other by IP
3. `ROS_DOMAIN_ID` set to same value (42) on both machines
4. `ROS_LOCALHOST_ONLY=0` configured on both machines
5. Node discovery works: PC can see nodes running on Pi via `ros2 node list`
6. Topic communication works: PC can pub/echo topics on Pi nodes

## Tasks / Subtasks

- [ ] Task 1: Configure network connectivity (AC: 1, 2)
  - [ ] Connect PC to WiFi network
  - [ ] Connect Pi to same WiFi network
  - [ ] Note IP addresses (e.g., `ip addr` or `hostname -I`)
  - [ ] Test: `ping <pi_ip>` from PC
  - [ ] Test: `ping <pc_ip>` from Pi
- [ ] Task 2: Configure ROS2 environment on Pi (AC: 3, 4)
  - [ ] Add to `~/.bashrc` on Pi:
    ```bash
    export ROS_DOMAIN_ID=42
    export ROS_LOCALHOST_ONLY=0
    ```
  - [ ] Source bashrc: `source ~/.bashrc`
- [ ] Task 3: Configure ROS2 environment on PC (AC: 3, 4)
  - [ ] Add to `~/.bashrc` on PC:
    ```bash
    export ROS_DOMAIN_ID=42
    export ROS_LOCALHOST_ONLY=0
    ```
  - [ ] Source bashrc: `source ~/.bashrc`
- [ ] Task 4: Test node discovery (AC: 5)
  - [ ] On Pi: `ros2 run demo_nodes_cpp talker`
  - [ ] On PC: `ros2 node list` - should show `/talker`
  - [ ] On PC: `ros2 topic list` - should show `/chatter`
- [ ] Task 5: Test topic communication (AC: 6)
  - [ ] On PC: `ros2 topic echo /chatter` - should show messages from Pi
  - [ ] On Pi: `ros2 run demo_nodes_cpp listener`
  - [ ] On PC: `ros2 topic pub /chatter std_msgs/msg/String "data: 'hello from PC'"`
  - [ ] Verify Pi listener receives message
- [ ] Task 6: Document network configuration
  - [ ] Record static IPs or hostnames in `docs/guides/network-setup.md`
  - [ ] Document any firewall rules if needed

## Dev Notes

### ROS2 Multi-Machine Requirements
- **Same `ROS_DOMAIN_ID`**: Nodes only discover others on same domain (0-101)
- **`ROS_LOCALHOST_ONLY=0`**: Must be disabled for network discovery
- **DDS Discovery**: Uses UDP multicast (ports 7400-7500 range)
- **Firewall**: May need to allow UDP traffic

### Network Topology
```
┌─────────────┐     WiFi      ┌─────────────┐
│     PC      │◄─────────────►│     Pi      │
│ 192.168.x.A │  ROS_DOMAIN   │ 192.168.x.B │
│   ID=42     │      =42      │   ID=42     │
└─────────────┘               └─────────────┘
```

### Troubleshooting
- **Nodes not discovered**: Check `ROS_DOMAIN_ID` matches exactly
- **Firewall blocking**: `sudo ufw allow 7400:7500/udp`
- **Multicast issues**: Some routers block multicast; try wired connection

### Testing

- **Test**: `ros2 node list` on PC shows nodes from Pi
- **Test**: `ros2 topic echo` on PC receives messages from Pi talker
- **Test**: `ros2 topic pub` from PC triggers response on Pi
