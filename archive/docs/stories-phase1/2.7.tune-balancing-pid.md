# Story 2.7: Fine-Tune Self-Balancing PID Parameters

## Status: Draft

## Story

**As a** builder,
**I want** PID parameters tuned for stable balancing,
**so that** the robot maintains balance reliably.

## Acceptance Criteria

1. Kp, Ki, Kd tuned systematically
2. Robot balances on flat surface for 60+ seconds
3. Robot recovers from small disturbances
4. Final parameters documented in firmware and README
5. Balancing video recorded

## Tasks / Subtasks

- [ ] Task 1: Prepare tuning environment (AC: 1)
  - [ ] Ensure robot is on flat, hard surface (not carpet)
  - [ ] Have someone nearby to catch robot during tuning
  - [ ] Connect serial monitor for real-time PID output
  - [ ] Prepare a spreadsheet or log to record Kp/Ki/Kd attempts and results
  - [ ] Verify emergency stop works before beginning

- [ ] Task 2: Tune Kp (proportional) first (AC: 1)
  - [ ] Set Ki=0, Kd=0
  - [ ] Start with low Kp (e.g., 1.0) — robot should lean and fall slowly
  - [ ] Increase Kp gradually until robot oscillates back and forth
  - [ ] Note the Kp value where oscillation starts (Ku — ultimate gain)
  - [ ] Set Kp to ~0.6 × Ku as starting point (Ziegler-Nichols rough estimate)
  - [ ] Record results for each Kp value tried

- [ ] Task 3: Tune Kd (derivative) second (AC: 1)
  - [ ] Keep Kp from Task 2, Ki=0
  - [ ] Start with small Kd (e.g., 0.01)
  - [ ] Increase Kd until oscillations from Kp are damped
  - [ ] Too much Kd → jittery/noisy response (amplifies sensor noise)
  - [ ] Find the Kd that gives smooth, damped response
  - [ ] Record results

- [ ] Task 4: Tune Ki (integral) last (AC: 1)
  - [ ] Keep Kp and Kd from above
  - [ ] Start with very small Ki (e.g., 0.1)
  - [ ] Ki corrects for steady-state offset (robot drifting to one side)
  - [ ] Too much Ki → slow oscillation, overshoot
  - [ ] Find Ki that eliminates drift without introducing oscillation
  - [ ] Verify anti-windup is working (hold robot, release — should not overshoot)
  - [ ] Record results

- [ ] Task 5: Fine-tune balance angle setpoint (AC: 2)
  - [ ] The balance angle may not be exactly 0° due to center of gravity offset
  - [ ] Adjust PID setpoint angle (±1-3°) until robot stays roughly stationary when balanced
  - [ ] This may shift as weight distribution changes (e.g., after mounting head/torso)

- [ ] Task 6: Validate 60-second balance (AC: 2, 3)
  - [ ] Run balancing with tuned parameters on flat surface
  - [ ] Time how long robot maintains balance — target 60+ seconds
  - [ ] Apply small pushes — robot should recover (AC: 3)
  - [ ] Test on slightly uneven surface
  - [ ] If balance fails, iterate on PID values (repeat Tasks 2-4)

- [ ] Task 7: Document and save parameters (AC: 4)
  - [ ] Update PID constants in firmware source code (`balancing_controller.h` or config)
  - [ ] Document final Kp, Ki, Kd, setpoint in `modules/base/README.md`
  - [ ] Document tuning methodology and key observations
  - [ ] Document BNO085 rotation vector report type used (rotation_vector vs game_rotation_vector)
  - [ ] Note any sensor orientation corrections applied

- [ ] Task 8: Record balancing video (AC: 5)
  - [ ] Record video showing 60+ seconds of stable balancing
  - [ ] Record video showing disturbance recovery (small push)
  - [ ] Save video to project documentation or link in README
  - [ ] Optionally record serial monitor output alongside video

## Dev Notes

### PID Tuning Methodology

This story is primarily a manual tuning/testing effort, not a software development task. The firmware from Story 2.6 provides the PID framework — this story tunes the gains for the actual physical robot.

### Tuning Approach: Modified Ziegler-Nichols

1. **P-only:** Increase Kp until sustained oscillation → note Ku (ultimate gain) and Tu (oscillation period)
2. **PD:** Add Kd to damp oscillation
3. **PID:** Add small Ki to eliminate steady-state error

Alternative: **Manual "feel" tuning** — common for self-balancing robots:
- Kp: Controls "stiffness" — how aggressively it corrects
- Kd: Controls "damping" — how quickly oscillations decay (use gyro rate directly)
- Ki: Controls "drift correction" — eliminates slow creep in one direction

### Typical Self-Balancing PID Ranges

For hoverboard-sized robots (15-25 kg), typical PID ranges:

| Parameter | Typical Range | Starting Value |
|-----------|---------------|----------------|
| Kp | 3-20 | 5.0 |
| Ki | 0-5 | 0.5 |
| Kd | 0.01-2.0 | 0.1 |
| Setpoint | -5° to +5° | 0.0° |

**Note:** These are rough guides. Actual values depend on weight, motor torque, wheel diameter, and IMU mounting orientation. The BNO085 on-chip AHRS provides filtered euler angles directly — no complementary filter alpha to tune.

### Serial Monitor Output Format

During tuning, the firmware (from Story 2.6) logs:
```
[INFO] Base: Loop: 4.8ms | Pitch: 1.2° | PID: 0.3 | Motor: 0.15 t/s
```

Use this to observe:
- Loop timing consistency (should be ~5ms / 200Hz)
- Pitch angle stability (should hover near setpoint)
- PID output magnitude (should be smooth, not jerky)

### Common Issues

- **Robot oscillates rapidly:** Kp too high or Kd too low
- **Robot falls slowly in one direction:** Ki too low or setpoint offset needed
- **Robot jitters/vibrates:** Kd too high (amplifying sensor noise) — lower Kd or increase D-term filter
- **Robot overshoots after push:** Ki too high — reduce Ki
- **Motors spin opposite direction:** Negate PID output or swap ODrive axis mapping

### Dependencies

- Story 2.4: Base platform assembled
- Story 2.5: ODrive configured and calibrated
- Story 2.6: Firmware with PID loop running at 200Hz

### Safety

- **Always have someone ready to catch the robot** during tuning
- Emergency stop must be accessible
- Start tuning with wheels on a stand (off ground) to verify motor direction
- Low battery can affect balancing — charge before tuning sessions

### Testing

This is a manual tuning/validation story. No automated tests — the test IS the 60-second balance and disturbance recovery.

**Pass criteria:**
- 60+ seconds of continuous balancing on flat surface
- Recovery from light push (1-2 cm displacement)
- No sustained oscillation (damped within 2-3 cycles)
- Loop timing stays within 5ms budget
