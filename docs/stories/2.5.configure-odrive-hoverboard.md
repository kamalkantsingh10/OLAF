## Dev Notes

### ODrive v3.6 Overview

The ODrive v3.6 is a dual-axis BLDC motor controller supporting:
- Closed-loop velocity and position control
- Hall sensor or encoder feedback
- UART, USB, CAN, PWM control interfaces
- Configurable current and velocity limits
- Hardware brake resistor support

### Hoverboard Motor Specifications (Typical)

| Parameter | Typical Value | Notes |
|-----------|---------------|-------|
| Type | BLDC (brushless DC) | Outrunner hub motor |
| Pole pairs | 15 | Verify by counting magnets ÷ 2 |
| Voltage | 36V nominal | Match battery voltage |
| Power | 250-350W per motor | Continuous rating |
| Hall sensors | 3-wire (A, B, C) | Built into motor |
| Max current | ~15A per motor | Check stall current |

### ODrive UART Protocol

The ESP32 communicates with ODrive via UART (ASCII protocol):
```
# Set velocity (turns/sec)
v 0 0.5\n       # axis0, 0.5 turns/sec
v 1 -0.5\n      # axis1, -0.5 turns/sec

# Read encoder feedback
f 0\n            # Returns: pos vel (turns, turns/sec)

# Set state
w axis0.requested_state 8\n   # CLOSED_LOOP_CONTROL
```

### Pin Connections (ESP32 → ODrive)

| ESP32 GPIO | ODrive Pin | Function |
|------------|------------|----------|
| GPIO 39 (TX) | GPIO 1 (RX) | ESP32 sends commands (J3 right header) |
| GPIO 38 (RX) | GPIO 2 (TX) | ESP32 receives feedback (J3 right header) |
| GND | GND | Common ground |

### Safety Considerations

- **Always calibrate with wheels off ground** — motors spin during calibration
- **Start with low current limits** — increase gradually
- **Use a fuse** between battery and ODrive
- **Emergency stop** must cut power before ODrive
- **Never change motor configuration while motors are spinning**
