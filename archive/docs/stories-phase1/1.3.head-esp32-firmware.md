# Story 1.3: Develop Head ESP32 Firmware

## Status: Ready for Review

## Story

**As a** builder,
**I want** ESP32 firmware that implements I2C slave interface and drives both eye displays,
**so that** the Pi can send expression commands via I2C.

## Acceptance Criteria

1. PlatformIO project created in `modules/head/firmware/`
2. I2C slave interface implemented at address 0x10 with register map defined
3. GC9A01 driver implemented using TFT_eSPI or equivalent library
4. Eye animation system: supports multiple expressions (neutral, happy, sad, surprised, angry, sleepy, wink)
5. Smooth transitions between expressions (interpolated animation)
6. Basic I2C commands work: `SET_EXPRESSION`, `SET_BLINK`, `SET_LOOK_DIRECTION`
7. Frame rate maintains 30+ FPS during animations
8. Firmware flashed to ESP32 and responds to I2C commands from Pi
9. OTA (Over-the-Air) update capability implemented with partition scheme and rollback support

## Dev Notes

### Hardware Configuration

**ESP32-S3-DevKitC-1 (N16R8):**
- I2C Address: 0x10
- Flash: 16MB, PSRAM: 8MB
- CPU: Xtensa LX7 dual-core @ 240MHz

**Pin Assignments (from esp32-pinout.md):**

| Function | GPIO | Notes |
|----------|------|-------|
| I2C SDA | 8 | To Pi GPIO 2, 4.7kΩ pull-up |
| I2C SCL | 9 | To Pi GPIO 3, 4.7kΩ pull-up |
| SPI MOSI | 11 | Shared for both displays |
| SPI CLK | 12 | Shared for both displays |
| Eye 1 CS | 10 | Left eye chip select |
| Eye 1 DC | 13 | Left eye data/command |
| Eye 1 RST | 14 | Left eye reset |
| Eye 2 CS | 15 | Right eye chip select |
| Eye 2 DC | 16 | Right eye data/command |
| Eye 2 RST | 17 | Right eye reset |

**Reserved GPIOs (DO NOT USE):**
- GPIO 26-32: Internal flash
- GPIO 33-37: Internal PSRAM
- GPIO 0, 3, 45, 46: Strapping pins

**Display Specifications:**
- 2× GC9A01 round OLED (240×240, 1.28")
- SPI speed: 10-20 MHz for 30-60 FPS
- Color: 65K RGB

### OTA Configuration

**Framework:** ESP32 Arduino OTA (built-in)

**Partition Scheme:** `min_spiffs` or custom with dual app partitions
```ini
# platformio.ini
board_build.partitions = min_spiffs.csv
; Or for 16MB flash with larger app:
; board_build.partitions = default_16MB.csv
```

**Partition Layout (min_spiffs.csv):**
| Name | Type | SubType | Offset | Size |
|------|------|---------|--------|------|
| nvs | data | nvs | 0x9000 | 0x5000 |
| otadata | data | ota | 0xe000 | 0x2000 |
| app0 | app | ota_0 | 0x10000 | 0x1E0000 |
| app1 | app | ota_1 | 0x1F0000 | 0x1E0000 |
| spiffs | data | spiffs | 0x3D0000 | 0x30000 |

**OTA Methods:**
1. **ArduinoOTA (WiFi)** - Requires WiFi connection, uses mDNS
2. **HTTP OTA** - Pull firmware from Flask server on Pi
3. **espota.py** - Command-line tool for pushing firmware

**Recommended:** HTTP OTA from Pi-hosted Flask server (no WiFi dependency on ESP32)

**Sample OTA initialization:**
```cpp
#include <ArduinoOTA.h>

const char* FIRMWARE_VERSION = "1.0.0";

void setupOTA() {
  ArduinoOTA.setHostname("olaf-head");
  ArduinoOTA.setPassword("olaf-ota-head");

  ArduinoOTA.onStart([]() {
    // Optionally show "updating" on eyes
  });

  ArduinoOTA.onEnd([]() {
    // Optionally show "complete" on eyes
  });

  ArduinoOTA.onError([](ota_error_t error) {
    Serial.printf("[ERROR] OTA failed: %u\n", error);
  });

  ArduinoOTA.begin();
}

void loop() {
  ArduinoOTA.handle();  // Must be called in loop
  // ... rest of loop
}
```

**OTA from Pi:**
```bash
# Using espota.py (requires WiFi on ESP32)
python3 ~/.platformio/packages/tool-espotapy/espota.py \
  -i olaf-head.local -p 3232 -f .pio/build/esp32s3/firmware.bin

# Or via HTTP server on Pi (preferred - no WiFi needed on ESP32)
# ESP32 fetches from: http://<pi-ip>:5000/firmware/head/latest.bin
```

### I2C Register Map

| Address | Name | R/W | Description |
|---------|------|-----|-------------|
| 0x00 | STATUS | R | 0=OK, 1=ERROR |
| 0x01 | COMMAND | W | Reserved for future commands |
| 0x10 | EXPRESSION_TYPE | W | 0=neutral, 1=happy, 2=sad, 3=surprised, 4=angry, 5=sleepy, 6=wink |
| 0x11 | EXPRESSION_INTENSITY | W | 1-5 (1=subtle, 5=extreme) |
| 0x12 | BLINK_TRIGGER | W | Write 1 to trigger blink |
| 0x20 | LOOK_X | W | Signed: -100 (left) to +100 (right) |
| 0x21 | LOOK_Y | W | Signed: -100 (down) to +100 (up) |

### Coding Standards

- **Language:** C++17
- **Naming:** camelCase for functions, snake_case for variables, PascalCase for classes
- **Constants:** `kPascalCase` or `UPPER_SNAKE_CASE` for macros
- **Memory:** No dynamic allocation in main loop (pre-allocate frame buffers)
- **Timing:** Use `millis()` for non-blocking timing, never `delay()` in loops
- **I2C ISR:** Keep interrupt handlers minimal (<10µs), set flags only

### Completion Notes List
- **Flicker fix**: Direct screen drawing caused visible flicker. Solved with TFT_eSprite (200x200 off-screen buffer in PSRAM). SPI bumped from 20MHz to 40MHz for fast sprite push.
- **Color unification**: Initially each expression had a distinct color. User preferred unified white — shape alone conveys emotion. LED strip matched to white (was cyan), except SPEAKING stays rainbow.
- **Eye sizing**: Initial 40px radius left too much black space on 240px round display. Bumped to 60px base, 85px max — fills display nicely against the black face surround.
- **Wake-up speed**: Initial 800ms felt slow. Reduced to 250ms (blink-speed eye open) per user feedback.
- **Two-layer architecture**: Layer 1 = system status (wake_level_ 0-1), Layer 2 = expression shape. Combined via `closedness = max(blink_amount, 1.0 - wake_level_)` — blink and sleep share the same visual mechanism.
- **Demo mode**: Firmware auto-cycles through all 6 statuses without Pi. Any I2C command disables demo mode and switches to Pi control.
- **OTA**: Uses shared OLAFota library rather than custom ota_handler.h/cpp. Partition scheme: default_16MB.csv with dual 6.5MB app partitions.
- **I2C**: REG_SYSTEM_STATUS (0x30) added for Pi to drive status transitions. Read handler deferred for later.
- **Angry mirror fix**: ANGRY expression was identical on both eyes. Fixed by marking ANGRY as asymmetric so `drawAngryV()` gets `is_right=true` for the right eye, mirroring the V-brow direction.
- **I2C pull-ups**: Pi 5 built-in 1.8kΩ pull-ups on GPIO 2/3 are sufficient — no external pull-up resistors needed for <30cm runs.
- **I2C testing complete**: All registers validated from Pi via `i2cset` — expressions, blink, look direction, system status, LED states all confirmed working.
