# Story 3.4: Create Neck ROS2 Driver Node

## Status: Draft

## Story

**As a** builder,
**I want** ROS2 driver node for Neck module via USB serial,
**so that** I can control head articulation via ROS2.

## Acceptance Criteria

1. Python ROS2 node created in `ros2/src/olaf_drivers/neck_driver/` (PRD says `ros2/src/olaf_neck/` — actual project uses `olaf_drivers/` parent)
2. Node subscribes to `/neck/pose` (pan, tilt, roll angles)
3. USB serial communication via scservo_sdk (vendored, wraps pyserial internally) to Waveshare adapter
4. Feetech servo protocol implemented
5. Smooth motion interpolation (optional)
6. Node launches and moves servos on topic publish

### Message Interface

**NeckPose.msg** (add to `ros2/src/olaf_interfaces/msg/`):
```
# Neck articulation command in degrees from center
float32 pan       # Left/right rotation in degrees (+ = left, - = right)
float32 tilt      # Up/down rotation in degrees (+ = up, - = down)
float32 roll      # Head tilt in degrees (+ = left tilt, - = right tilt)
float32 speed_pct # Motion speed 0.0-1.0 (0 = default speed)
```

### ROS2 Topics

| Topic | Message Type | Direction | Description |
|-------|--------------|-----------|-------------|
| `/olaf/neck/pose` | NeckPose | Subscribe | Commanded pan/tilt/roll angles |
| `/olaf/neck/status` | std_msgs/String | Publish (1 Hz) | Position feedback JSON |

### Servo Configuration (from config/servo-ids.yaml)

Neck section already has servo IDs defined. Story 3.1 will add calibrated values for:
- `center_position` — raw servo position at mechanical center
- `min_angle` / `max_angle` — software limits in degrees
- `direction` — mapping between positive degrees and servo count direction
- `counts_per_degree` — ~11.38 for STS3215

### STS3215 Motion Control

The STS3215 has built-in speed and acceleration control via `WritePosEx`:
```python
# sms_sts.WritePosEx(servo_id, position, speed, acceleration)
# speed: 0-4095 (steps/sec)
# acceleration: 0-254 (higher = smoother ramp)
sts.WritePosEx(1, 2048, 500, 50)
```

Map `speed_pct` from NeckPose message to STS3215 speed parameter. This provides hardware-level smooth interpolation without needing software interpolation in the node.

### Coding Standards

From `docs/architecture/coding-standards.md`:
- **Python:** PEP 8, max 100 chars, type hints required for public functions
- **Naming:** snake_case for functions/variables, PascalCase for classes
- **Imports:** stdlib → third-party → ROS2 → local
- **Docstrings:** Google style, required for public classes/functions
- **Error handling:** Catch specific exceptions, log with context via ROS2 logger
- **ROS2 node naming:** `<module>_<function>_node` under `/olaf/` namespace
- **ROS2 topics:** `/<namespace>/<module>/<data_type>`

### Pattern Reference: Ears ROS2 Node (Story 4.4)

The ears node (`ears_node.py`) provides the implementation pattern:
- Loads config from `servo-ids.yaml`
- Subscribes to expression + direct pose topics
- Publishes status at 1 Hz
- Centers servos and closes serial on shutdown
- Uses existing driver class from Story 4.1

Follow this same pattern for the neck node, adapting for 3-axis articulation (pan/tilt/roll) instead of 4-servo ear expressions.
